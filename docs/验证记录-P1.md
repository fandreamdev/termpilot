## 手工演示步骤

1. 执行 `npm run tauri:dev`。
2. 确认主机、终端、SFTP、Agent、审计五个页面均可切换，并各自显示空状态或加载状态。
3. 在“主机”页点击“测试连接”。
4. 应自动切换到“终端”页，依次看到 `session.status` 和 `session.output` Mock 事件；界面显示的最后序号应单调递增。
5. 关闭窗口，确认终端中没有残留的 TermPilot 后台进程；再次启动后可重复上述演示。

## 协议约定

- 前端仅通过 `invokeApi(command, request)` 调用 P1 Mock command；该封装为每次请求生成 UUID `request_id` 和 `correlation_id`。
- 后端成功和预期失败均返回 `{ok, request_id, data, error}`；错误只有安全的代码和面向用户的消息，不返回 Rust 堆栈或请求内容。
- 所有应用事件通过 `termpilot://event` 传输，带 `version`、递增 `seq`、`correlation_id`、UTC 时间和 `data`。
- `event_replay` 支持按 `after_seq` 重放最多 100 条当前进程内事件；持久化重放属于后续审计阶段。

## 已知限制与下一阶段

- Mock event history 只存在于当前应用进程，用于 P1 的断线重放接口验证，不是审计存储。
- P1 不保存主机、不连接 SSH、不创建 PTY 或 SFTP；这些能力分别属于 P2、P3、P4、P5。
- P0 独立 SSH PoC 仍保留在 `scripts/ssh-poc.ps1`，真实 localhost/授权堡垒机实测需具备获授权账号或本机 `sshd`。
